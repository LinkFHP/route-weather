# 路线天气体检 · 初项目

> 游客出发前输入一条旅游路线，得到一个一眼能看懂的「天气体检报告」：
> 明天这条路适不适合走、几点出发最稳、每个点逐小时什么天气、哪个点最难受。
>
> **不是导航，不是预警，是「行程的天气体检」。**

- 形态：**移动端 Web 应用（H5）**，手机浏览器直接打开，无需安装与登录
- 参赛：2026 第十四届全国大学生数字媒体科技作品及创意竞赛 · 主赛道 · 自主选题类（二）**移动与网络应用开发类**
- 技术栈：原生 HTML / CSS / JavaScript，**零构建、零依赖、零后端**
- 数据：Open-Meteo 公开气象预报（CC BY 4.0）

## 一、怎么跑起来

### 方式 A：本地起一个静态服务（推荐）

在本目录下执行任一：

```bash
# 有 Python
python -m http.server 8080

# 有 Node
npx serve .
```

然后浏览器打开 `http://localhost:8080`。
手机同 Wi-Fi 下可用 `http://<你的电脑IP>:8080` 在手机上实测。

> 为什么推荐起服务：直接双击 `index.html` 以 `file://` 打开时，部分浏览器会拦截
> `fetch` 跨域请求，导致取不到天气数据。

### 方式 B：直接双击 index.html

也能用，但若报告页提示取不到数据，请改用方式 A。

### 跑测试（需要 Node 18+）

```bash
node test/algo-test.js    # 联网，用真实 Open-Meteo 数据跑通整条链路
node test/edge-test.js    # 不联网，28 条边界断言
```

## 二、怎么部署上线（免费，几分钟出链接）

拿到的链接就是提交材料里的「**可访问版本**」。

### GitHub Pages（推荐，本仓库已按此配置）

仓库已初始化（`main` 分支）、已配好 `.gitignore` / `.gitattributes`，
所有资源路径都是**相对路径**，可直接部署在子路径 `https://<用户名>.github.io/<仓库名>/`。

**第一步：在 GitHub 上建一个空仓库**（不要勾选 README / .gitignore / license）

**第二步：本地推送**

```bash
cd route-weather
git config user.name  "你的名字"
git config user.email "你的邮箱"
git commit -m "feat: 路线天气体检 —— 双模式路线天气体检 H5 应用"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

**第三步：开启 Pages**

仓库 → **Settings → Pages** → Source 选 `Deploy from a branch`
→ Branch 选 `main`、目录选 `/ (root)` → Save

约 1 分钟后得到：`https://<用户名>.github.io/<仓库名>/`

> 提交前建议确认一遍：`index.html` 在仓库根目录（本仓库即是）。

### Vercel / Netlify（更简单，无需 git）

把整个文件夹拖进 Vercel 或 Netlify 的部署页面即可，自动出 HTTPS 链接。
适合只想快速拿链接、不想管 git 的情况。

> ⚠️ 必须是 **HTTPS** 链接（以上三种默认都是）。本项目不依赖定位权限，
> 但 HTTPS 仍是提交材料的规范要求。

## 三·补、地图可视化与视觉风格

### 视觉风格：参考高德地图

界面按高德地图的视觉语言重做：

| 元素 | 高德式做法 |
|---|---|
| 主色 | 品牌蓝 **#0091FF**，渐变 `#22A6FF → #0074E0` |
| 顶栏 | 白底 + 蓝色品牌方块标识 + 深色标题（不用彩色通栏） |
| 起点 / 终点标记 | **绿「起」/ 红「终」圆角气泡**，中间点用蓝色数字圆点 |
| 路线 | **蓝色主线 + 白色描边**（先画白描边、后画蓝主线） |
| 表单 | 浅灰填充（#F2F3F5）、无边框，聚焦时白底 + 蓝边 + 光晕 |
| 分段控件 | 灰色卡槽 + 白色高亮块 + 蓝色文字（配线性图标） |
| 卡片 | 圆角 14px + 轻投影；章节标题带蓝色竖条 |
| 底部弹层 | 20px 圆角上滑 + **拖拽条** |
| 按钮 | 蓝色渐变 + 投影，按下微缩 |

图标为内联 SVG（驾车 / 步行 / 骑行 / 点位 / 导航），不依赖图标库。

### 地图做了什么

| 位置 | 地图作用 |
|---|---|
| **新建行程** | 边加点边连线；**点地图任意位置可直接添加点位** |
| **体检报告** | 展示整条路线，**点位圆点按评分着色**；点地图上的点位 → 跳转并高亮对应卡片 |
| 底图切换 | 右上角一键在**标准图 / 地形图**之间切换（地形图有等高线，山区更有用） |

### 为什么不用高德/腾讯地图

它们需要注册 Key + **实名认证**，且国内瓦片用 GCJ-02 坐标系，与气象接口的 WGS-84 有数百米偏移。
本项目**优先选零门槛 + 坐标一致**的方案：

| 资源 | 用途 | 说明 |
|---|---|---|
| **Leaflet 1.9.4** | 地图引擎 | BSD-2，已**本地化**到 `vendor/`，不依赖 CDN |
| **OpenStreetMap 标准瓦片** | 底图 | 免费、无 Key、**WGS-84 与气象接口一致**；须署名 |
| **OpenTopoMap** | 地形底图 | 免费、无 Key、含等高线；许可 CC-BY-SA，须署名 |

> ⚠️ **瓦片使用政策要诚实说明**：OSM 与 OpenTopoMap 都是**社区公益瓦片**，
> 适合教学演示与低流量使用，**不适合大流量公开运营**。
> 若后续要真正上线，应改用商业瓦片服务或自建瓦片。
> 这一点已写入「已知限制」，评审问到可以坦然回答。

### 实测：底图选择是「中文 / 地形 / 国内直连」三选二

| 底图 | 注记 | 坐标系 | 国内直连 | 川西画面 |
|---|---|---|---|---|
| **天地图**（需免费 key） | 中文 | WGS-84 | ✅ | 有地形，**推荐** |
| **中文（高德 style=7）** | 中文 | **GCJ-02** | ✅ | ⚠️ 偏远山区几乎空白 |
| OSM | 中文/本地名 | WGS-84 | ❌ 常需代理 | 有地形，好看 |
| Esri Topo | **英文** | WGS-84 | ✅ | 有地形 |
| OpenTopoMap | 混合 | WGS-84 | 🟡 一般 | 有等高线 |

**关键坑（已处理）**：高德/腾讯底图是 **GCJ-02** 坐标系，而 Open-Meteo 与 OSRM 返回 **WGS-84**。
不做转换，点位会偏 **300–700 米**（实测川西约 340 m，往返误差 0.00 m）。
代码里已实现标准 `wgs2gcj` / `gcj2wgs` 双向变换，**切底图时会自动整图重建**——
因为坐标系变了，只换瓦片不够。

**实测发现**：高德 `style=7` 在川西偏远山区几乎不画内容 —— 泸定附近 z10 瓦片
**只有 4.0% 非白像素**（成都同 zoom 为 10.1%），地图会大片发白。
所以它能直连，但视觉不理想。

### 启用天地图（已配置 ✅）

`js/map.js` 顶部已填入 key，底图列表前两位是「**天地图**」（矢量）与「**天地地形**」（地形晕渲）。
换 key 或想关掉，只改这一行：

```js
const TIANDITU_KEY = '你的key';   // 置空则自动跳过天地图
```

> 这是「浏览器端」key，会出现在前端源码里，属正常。可在天地图控制台按域名限制用量。
> 免费额度对竞赛演示完全够用。

### 地图的降级设计

- 瓦片加载失败 → **自动切到下一套底图**（`tileerror` 监听，逐级降级并 toast 提示）
- 全部失败 → 显示「地图瓦片没能加载出来」+ **重试按钮**，不再是无声的一块灰
- 容器尺寸变化 → `ResizeObserver`（不存在时安全跳过）+ `invalidateSize` 重算
- **地图整体渲染包在 try/catch 里** —— 地图挂了只影响地图区域，天气数据/评分/列表照常
- 栅格底纹兜底，瓦片未到时也不是纯白块

### 踩过的两个坑（值得写进技术说明）

1. **不能在 `display:none` 的容器上初始化 Leaflet** —— 会抛
   `Cannot read properties of undefined (reading 'parentNode')`。
   解决：新建页地图**惰性初始化**，只在视图可见时创建。
2. **不要用 `polyline.bringToBack()`** —— 地图尚未渲染时 `_renderer` 未就绪会报错。
   解决：**先加白色描边、再加彩色主线**，用绘制顺序代替 `bringToBack`。

## 三·补二、导航模式（点位模式之外的第二条路）

### 两种模式的区别

| | 点位模式 | 导航模式 |
|---|---|---|
| 输入 | 起点 + 途经点 + 终点 | **起点 → 终点**（可加途经点） |
| 评估对象 | 就是你输入的点位 | **沿规划路径等距采样出的点** |
| 天气取哪个时刻 | 所有点位取**同一时刻** | 每个采样点取**预计到达该点那一刻** |
| 地图 | 点位连线（示意） | **真实规划路径**（路网几何） |
| 适合 | 自己定好停哪几个点 | 只想"从 A 到 B 这一路怎么样" |

### 为什么"到达时刻"是关键

成都 → 稻城 约 7.9 小时车程。如果第 8 个采样点也用出发时刻的天气去评估，
等于在说"早上 8 点的天气决定了下午 4 点折多山的路况"——这在山区是错的。

导航模式对第 i 个采样点：
```
预计到达时刻 = 出发时刻 + (该点里程 / 总里程) × 总时长
评分 = 用「预计到达时刻」那一小时的天气算
```

实测输出（雅安 → 康定 → 稻城，547 km）：

| 采样点 | 距起点 | 预计到达 | 评分 | 扣分 |
|---|---|---|---|---|
| 雅安 | 0 km | 12:00 | 100 | — |
| 途采1 | 78 km | 13:00 | 100 | — |
| 途采2 | 156 km | 14:00 | 95 | 高海拔 3976 m（−5） |
| 途采3 | 235 km | 15:00 | 95 | 高海拔 3447 m（−5） |
| … | | | | |

### 采样规则

- **按里程等距采样**，不是按几何点索引（路网几何点疏密不均，按索引会挤成一团）
- 采样点数 ≈ **每 45 分钟一个点**（天气在 45 分钟内变化有限），限 **3–8 个**
- 采样后**取两天预报**（48 小时），因为到达时刻可能跨过零点

### 推荐出发时刻

遍历 `0–23` 点出发，计算每个出发时刻下**全程最低分**，取最高的那个 —— 
即"最稳"的出发时刻，而不是"全天分数最高"的时刻。安全场景必须保守。

### ⚠️ 必须诚实交代的三件事（已写进界面）

1. **OSRM 公共 demo 服务只有汽车路网** —— `bike`/`foot` 会**静默返回与 `driving` 相同的结果**
   （实测：成都→稻城三个 profile 都是 681 km / 7.9 h）。
   所以徒步/骑行模式界面会显著提示「路径与时长按公路网估算」。
2. **时长偏乐观** —— 按路网限速估算，山区实际车速更慢，建议预留 20–30% 余量。
3. **只评估采样点** —— 采样点之间的小段不在评估范围内，且未考虑堵车、休息、封路。

## 四、核心设计要点（可写进作品介绍）

### 1. 短板原则：路线分 = 各点最低分

一个人可以在 85 分的路段上走，但整条行程的安全性由**最差的那一段**决定。
报告里同时给出平均分作为参考，避免算法显得粗暴。

### 2. 不可解释即不输出

任何分数都必须能列出主要扣分项（降水概率 / 降水量 / 风速 / 气温偏离 / 天气现象 / 高海拔），
报告上固定显示前 3 项扣分原因。**列不出原因就不显示分数。**

### 3. 出发窗口做了"有意义"的处理

若当天有 19 个小时都达到「一般」，报「19 小时窗口」是没有意义的。
因此算法在合格时段内**滑窗取最优的、且不超过 6 小时的一段**，并说明当天共有多少时段达标。

### 4. 没有窗口时不只说"无"

降级为输出：**最接近时段 + 全线最低分 + 瓶颈点位名称**，
让用户知道"差在哪、可以怎么调整"，而不是一句冷冰冰的"无合适窗口"。

### 5. 高海拔额外扣分

海拔 > 3000 m 额外扣 5 分 —— 这是通用天气 App 不会做的，
也是本作品面向**山区路线**的差异化点。

## 六、已实测的接口事实（2026-10-17）

| 项目 | 结果 |
|---|---|
| CORS | `Access-Control-Allow-Origin: *` → 浏览器可直连，**无需后端/代理/备案** |

## 七、已知限制（**主动写进材料，不要藏**）

1. **仅评估输入的点位**，点位之间的路段不在评估范围内（报告页已固定说明）。
2. **山区局地精度有限** —— Open-Meteo 为全球模型，川西高山峡谷地形复杂。
3. **点位库覆盖有限** —— 本期 23 个川西/川北点位，不支持任意地名搜索。
4. **海拔来自 Copernicus DEM** —— 陡峭河谷中可能读到坡面而非聚落高度。
5. **地图底图为社区公益瓦片**（OSM / OpenTopoMap），适合教学演示与低流量，
   **不适合大流量公开运营**；正式上线需改用商业瓦片或自建瓦片。
6. **地图不是导航** —— 只画点位连线，不提供路径规划、路况或封路信息。
7. **未实现功能**：分享卡片、订阅提醒、长图导出、多行程对比、语音播报、用户上报路况。
8. **不发布预警**、不提供实时路况、不做路径规划 —— 无相应数据源与发布权。

> 这些都写清楚比藏起来得分高。官方明确要求「**如实区分已完成内容、测试内容和计划内容**」，
> 谎报才违规。
